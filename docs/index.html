Validated end-to-end on a real device

Your WhatsApp history. Android to iPhone. Without starting over.

OATH is an open-source tool that moves your real chat history, media, and stickers to a new iPhone — without Apple's "Move to iOS" (which doesn't carry WhatsApp) and without paid software.

View on GitHub Quickstart

Why this exists

Apple's own migration tool doesn't move WhatsApp chat history between platforms. The alternative is closed-source paid software of unknown reliability, run against your most personal data. OATH decrypts your own export with your own key, runs entirely on your machine, and sends nothing anywhere.

Real data, real restore

Converted a real crypt15 export — 1,622 chats, 64k+ messages, 11.5k+ media files — and restored it to a real iPhone via Apple's own MobileBackup2 protocol. No errors.

100% local

No server, no account, no upload. Decryption key and chat data never leave your computer.

Open source, GPL-3.0

Every byte of the conversion and restore logic is readable, forkable, and auditable — including the exact bugs found and fixed against a real device.

Search your own history

Built-in full-text search over your decrypted chat history, from the CLI or a local-only web GUI. Nothing indexed ever leaves your machine either.

Quickstart

Needs Python 3.10+ and uv.

uv sync
uv run oath doctor                       # tool and device check
uv run oath emulate /tmp/oath-demo       # try it on synthetic data first
uv run oath convert --android /path/to/WhatsApp --key <64-hex> \
    --ios-backup /path/to/unencrypted/backup --out /tmp/ios-converted
uv run oath search-build --android /path/to/WhatsApp --key <64-hex> --out ~/wa-search.db
uv run oath search-gui ~/wa-search.db    # http://127.0.0.1:8765, local only

Built on real-device evidence, not guesses

Apple's restore-time validator checks far more than file bytes. Getting a converted backup to actually restore — not just build — took diagnosing two silent record-encoding bugs against a real device, using its own live syslog to find what the restore protocol's own error message didn't say.

  1. Digest encoded inline instead of as an object reference. Round-trips fine through OATH's own reader; Apple's real NSKeyedUnarchiver rejects it outright during restore.
  2. Missing ProtectionClass on written files. Every real WhatsApp file carries class 3; without it the device fails to open the file with EINVAL.
  3. Both fixed, both confirmed on all 11,543 written files — the restore then completed to 100% with no errors.
