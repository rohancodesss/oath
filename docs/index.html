android → iphone · whatsapp chat history · restored on a real device, 0 errors

Moves your WhatsApp history to a new iPhone. Not Apple's migration tool. Not paid software.

"Move to iOS" doesn't carry WhatsApp chats across. OATH decrypts your own crypt15 export with your own key, converts it to the iPhone backup format, and restores it through Apple's own MobileBackup2 protocol — entirely on your machine.

$ oath convert --android ~/WhatsApp --key <64-hex> \
    --ios-backup ~/ios-backup --out ~/ios-converted
source: 1622 chats, 64145 messages, 11543 media
written to ~/ios-converted: 1622 chats added, 64145 messages, 11543 media files

$ pymobiledevice3 backup2 restore ~/ios-converted

Restoring finished. EXIT: 0

what it does

Android → iPhone
Decrypts a real crypt15 WhatsApp export, maps messages/media/groups/stickers/quotes into the iPhone's Core Data schema, writes them into a copy of an unencrypted iPhone backup.
Restores for real
The output backup passes Apple's own restore-time validation and restores through Finder or pymobiledevice3 — not just "builds," actually restores.
Search your history
Local SQLite full-text index over your decrypted chats, queryable from the CLI or a local-only web GUI (127.0.0.1, nothing leaves the machine).
Not done yet
Quoted-reply links and starred flags don't carry over to iOS (reported as warnings). iPhone → Android isn't built.

quickstart

# needs python 3.10+ and uv
$ uv sync
$ uv run oath doctor                       # tool and device check
$ uv run oath emulate /tmp/oath-demo       # try it on synthetic data first
$ uv run oath convert --android /path/to/WhatsApp --key <64-hex> \
    --ios-backup /path/to/unencrypted/backup --out /tmp/ios-converted
$ uv run oath search-gui ~/wa-search.db    # http://127.0.0.1:8765

why it's not simpler than this

Apple's restore-time validator checks far more than whether bytes are present. Getting a converted backup to actually restore — not just build — meant diagnosing two silent record-encoding bugs against a real device, using its own live syslog to find what the restore protocol's own error message left out.

FAIL
ErrorCode 205 — "Multiple errors downloading files"No file named. Every file OATH had written failed the same way; the protocol's own error gave no detail.
FOUND
Digest stored inline instead of as an object referenceRound-trips fine through OATH's own reader; the real device's NSKeyedUnarchiver rejects an inlined data literal where it expects a UID-referenced object.
FOUND
Missing ProtectionClass on written filesEvery real WhatsApp file carries class 3. Without it the device defaults to class 0 and fails to open the file with EINVAL.
FIXED
Both patched, confirmed on all 11,543 written filesRestore then completed to 100% with exit code 0. Full root-cause writeup in the repo.
